## Reading these numbers honestly

Database-side work is not the bottleneck at this volume. The slowest query returns in 4.11 ms and the entire documented analysis suite runs in 32.8 ms, so Tableau extracts, refreshes and renders without perceptible latency.

Page generation is likewise flat: the slowest route (Global EV Insights) serves a median of 5.1 ms and 2.4 KB of HTML, because Flask touches no database at runtime and only composes templates around an iframe.

**The real latency budget is the Tableau embed itself.** A published public view pulls the workbook's extract plus Tableau's own runtime over the network, typically one to five seconds, which is why `static/js/embed.js` shows a skeleton and falls back to a direct Tableau Public link after 20 seconds. Any performance complaint during a demo will come from that network fetch, not from Postgres or Flask.

### Scaling headroom

1,263 rows is a small dataset by BI standards. To demonstrate behaviour at volume, extend `YEARS` in `scripts/generate_dataset.py` or add model lines; the fact grain is (model, year, variant, chemistry), so a 2015-2030 window plus 400 models yields roughly 150,000 rows. Postgres and a Tableau extract both handle that comfortably, and no query here depends on the current row count.
