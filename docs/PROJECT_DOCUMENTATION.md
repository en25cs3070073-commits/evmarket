# Step-by-step development procedure

How this project was built, in order, with the decisions that shaped it. Every command here is
the command that was actually run.

## Architecture

```
scripts/generate_dataset.py
        |  writes
        v
data/ev_market_dataset.csv  (1,263 rows x 26 cols)
        |  scripts/load_db.sh  ->  docker compose up postgres:16
        v
stg_ev_raw  ->  v_stg_clean (type + null cleansing)  ->  star schema
                                            country, vehicle_model, ev_variant_sales
        |  10 analytic views, 16 analysis queries
        v
v_ev_data + aggregates
        |  Tableau Public Desktop (Extract)  ->  3 dashboards + 1 story
        v
public.tableau.com/views/...
        |  URLs pasted into tableau_urls.json
        v
Flask (app.py)  ->  Vercel  ->  one public URL
```

## Epic 1 — Problem understanding

Produced [PROBLEM_STATEMENT.md](PROBLEM_STATEMENT.md): the three personas as three views of one
system, 13 KPIs each defined as a formula plus the SQL object that computes it, and 14 business
questions mapped to specific queries with their answers.

**Decision.** The three scenarios are not three applications. Dashboard boundaries were drawn by
persona *pair* (Emily+David, Emily+Sarah, David+Sarah) so every persona is fully served by exactly
two dashboards and nothing is built twice.

## Epic 2 — Data collection and database

The intended source was
[EV Market Analytics 2026](https://www.kaggle.com/datasets/patelris/electric-vehicle-market-and-pricing-dataset-2026).
It matched the brief's column list almost exactly, but three findings changed the plan:

1. It is **also synthetic** — generated by a published Python script with seed 42.
2. It has **no battery-chemistry column**, which the brief names as core to Dashboard 2 and to the
   entire research persona.
3. It computes `range = capacity x 3.5 + noise` globally, so the recommended "capacity vs range"
   scatter would be a straight line — a chart of the generator, not of the market.

Downloading it also requires Kaggle credentials, which returned a login page instead of a file.
So the project generates its own dataset with the same intent and better properties.

`scripts/generate_dataset.py` builds a catalogue of 116 real vehicle lines — real brands, models,
segments, countries of origin and chemistries — then expands each across 2018-2025 with trims.
Range is `capacity / per-model Wh-per-mile`, where efficiency differs by body type and trim, so the
scatter shows three readable bands instead of one line. Grid carbon intensity per country is
external published data, not invented.

**Schema.** Three tables in a star: `country` (11 rows), `vehicle_model` (119), `ev_variant_sales`
(1,263). Fact grain is **(model, year, variant, battery_technology)** — chemistry sits on the fact
because the same model can ship different cells (NIO ET7 appears with both NMC and a 150 kWh
semi-solid-state pack).

**Credentials.** `ev / ev_local_only` on `localhost:5432`. These are local-only development values
in `docker-compose.yml`; nothing connects to the internet and no real secret exists here.

## Epic 3 — SQL operations

`db/load.sql` implements a real ETL rather than a bulk insert:

1. `stg_ev_raw` — all 26 columns land as `TEXT`, exactly as the file provides them.
2. `is_numeric()` plus explicit casts and range guards in `v_stg_clean` reject untypable rows.
3. Three `INSERT ... SELECT` statements build country, then the dimension (GROUP BY with
   MIN/MAX year), then the fact (joined on the four natural-key columns).
4. A reload report prints staged, clean, rejected, and total-volume counts.

Measured behaviour: the schema rebuild and the full ETL each complete in well under a second, and
server-side execution across all 16 analysis queries totals roughly 33 ms. Exact figures are in
[PERFORMANCE_TESTING.md](PERFORMANCE_TESTING.md), which `scripts/perf_test.py` regenerates so these
claims never go stale.

`db/analysis_queries.sql` holds 16 labelled queries covering `SUM`, `AVG`, `COUNT`, `COUNTD`,
`GROUP BY`, `HAVING`, four kinds of window function (`SUM() OVER`, `ROW_NUMBER`, `RANK`, `LAG`),
CTEs, self-joins, `CASE` bucketing and a Herfindahl-Hirschman index. Results are captured in
`analysis_results.txt`.

## Epic 4 — Data preparation

The relational split from Epic 3 is the preparation. `v_ev_data` then joins the star back into one
31-column wide table and adds five derived measures in SQL rather than letting Tableau invent them:
`gwh_battery_demand`, `co2e_avoided_tonnes`, `usd_per_1000_miles`, `usd_per_kwh`, and the joined
`grid_intensity_kgco2_per_kwh`.

`scripts/export_tableau.sh` writes the 10 analytic views to `data/tableau/`, which is the documented
fallback if Tableau Public declines a database connection.

**Data dictionary.** Types and constraints are enforced by `db/schema.sql`; the columns are:

| Column | Meaning |
|---|---|
| `brand`, `model_name`, `variant_name` | Vehicle identity; variant is Standard Range / Long Range / Performance / Base |
| `model_year` | 2018-2025 |
| `body_type` | Sedan, SUV, Hatchback, Truck, Van, Bus, Two-Wheeler |
| `market_segment` | Budget, Mainstream, Premium, Luxury, Commercial |
| `powertrain_type` | BEV, EREV |
| `battery_technology` | LFP, NMC, NCA, Sodium-Ion, Semi-Solid-State |
| `country_of_origin` | Manufacturing country; also used as the grid proxy |
| `battery_capacity_kwh` | Usable pack capacity for that variant and year |
| `driving_range_miles`, `driving_range_km` | Capacity divided by modelled efficiency |
| `energy_consumption_wh_per_mi` | Modelled efficiency, improves ~0.6% a year |
| `peak_charging_kw`, `charging_time_min_10_80` | Charger rating and derived DC refill time |
| `acceleration_0_60_mph`, `top_speed_mph`, `horsepower`, `seating_capacity` | Performance and packaging; 0-60 is not meaningful for buses and heavy trucks |
| `price_usd` | Modelled MSRP with deflation and the 2023+ price war |
| `annual_sales_units` | Modelled volume in that year for that variant |
| `customer_rating` | 3.0-4.9 composite; for commercial vehicles this is operator satisfaction |
| `safety_rating` | 1-5 star |
| `est_manufacturing_co2e_tonnes` | Body base + capacity x chemistry factor x grid factor |
| `est_annual_co2e_saved_tonnes` | ICE tailpipe baseline for that body type minus grid-based charging emissions |

## Epic 5 — Visualisations

Specified in [TABLEAU_BUILD_SPEC.md](TABLEAU_BUILD_SPEC.md): 15 worksheets (W1-W15) each mapped to
exact columns, mark type and the dashboard it feeds, plus 15 calculated fields, one of them built
from two `FIXED` level-of-detail aggregations. Authoring itself is GUI work in Tableau Public
Desktop and is the remaining human step.

## Epic 6 — Dashboards and story

Three dashboards at 1600x900 fixed, each with a **Phone** device layout, plus a four-scene story
whose captions are pre-written with their figures. Six interactive filters are shared across
dashboards.

## Epic 7 — Flask integration and testing

`app.py` reads `tableau_urls.json` as its only configuration and serves `/`, `/market`, `/battery`,
`/global`, `/story`. Embedding uses an iframe with `:embed=true`, and `static/js/embed.js` reveals
the frame on `load`, shows a skeleton before that, and offers a Tableau Public fallback after 20
seconds.

Two design points worth defending:

- **Flask never touches the database.** The published Tableau extract is the snapshot, so the
  deployed app has no connection string, no driver and no secret. This is what makes a free static
  function host viable.
- **A page without a URL is a documented state, not a bug.** It renders the analytical brief, so
  the site is presentable at every stage of the build.

`scripts/validate.py` runs 42 checks across the dataset, warehouse and routes and exits non-zero on
failure. `scripts/perf_test.py` regenerates the performance report from live measurements.

## Defects found and fixed during the build

Recorded because "how did you notice" is a fair viva question and the answers are all detectable
by the validation suite now.

| Symptom | Cause | Fix |
|---|---|---|
| `customer_rating` min equalled max at 2.6 | Composite topped out near 1.42 while the clamp floor was 2.6, so every row pinned to the floor | Rank the composite across the dataset, then map onto 3.05-4.85; range now 3.00-4.85 |
| Battery demand read 490,000 "GWh" for 2025 | Divided kWh by 1,000 instead of 1,000,000 | Corrected divisor in all four views; 2025 is 490 GWh |
| Multi-trim brands looked 2-3x larger than rivals | Each variant received the model's entire peak volume | Peak split across variants by share, then normalised |
| Buses showed ~120 mile range, trucks ~106 | Placeholder Wh/mi figures far too high for commercial vehicles | Corrected per-model efficiency; a 552 kWh eCascadia now reads 251 mi |
| "SUVs grew 48,486%" | Most catalogue models launch after 2018, so absolute growth measured catalogue coverage | Q4 now reports share-of-year movement (SUV +22.9 pts) and the caveat is documented |
| USA avoided the most CO2 per vehicle despite a coal-heavy grid | US rows are dominated by electric trucks, whose diesel baseline is enormous | Q11 holds body type constant: Sweden 2.54 t, Vietnam 1.23 t |
| Solid-state range advantage hidden | A sodium-ion bus sat in the same average | Q15 compares passenger vehicles only: 402 vs 302 miles |
| Tableau embed stayed on "Loading" forever | `viz_v1.js` and `tableau-2.min.js` expose no `TableauEventType` and its `Viz` has no `addEventListener` | Replaced the JS-API approach with an iframe plus a load-timeout fallback |
| `load.sql` failed on a second run | `DROP TABLE stg_ev_raw` could not cascade to the view depending on it | Added `CASCADE`; reload is now idempotent |

